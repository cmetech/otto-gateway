<objective>
Add a darwin-arm `golangci-lint` job to `.github/workflows/ci.yml` so the darwin
build arm stops drifting unlinted.

`cmd/otto-tray` is tagged `//go:build darwin || windows`, and seven of its files
are darwin-only (`desktop_darwin.go`, `openfolder_darwin.go`,
`autostart_darwin.go`, `pidfile_darwin.go`, `uihelpers_darwin.go`,
`trayhooks_darwin.go`, `desktopconsole_darwin.go`), plus
`cmd/otto-tray/icon/icon_darwin.go` and `internal/procstat/procstat_other.go`.
The existing `lint-test-arch` job runs on `ubuntu-latest`, where every one of
those is excluded by build tag — so they are linted nowhere. Two real findings
sat undetected in them until quick task 260725-gp6 found them by hand on a mac.

Purpose: a darwin-only lint regression shows up as a red X in the PR check list
instead of surviving until a developer happens to lint on a mac.
Output: one new job in one workflow file. No Go source changes.
</objective>

**Finding 1 — `macos-latest` is required. A linux runner with `GOOS=darwin`
cannot do this job, at any `CGO_ENABLED` setting. PROVEN, not assumed.**

golangci-lint must load and type-check a package before any linter runs. On
darwin, `cmd/otto-tray` pulls in `github.com/energye/systray`, whose darwin
implementation is a cgo file — confirmed at
`$(go env GOMODCACHE)/github.com/energye/systray@v1.0.3/systray_darwin.go`,
the only file in that module importing `"C"`.

- With cgo ON, a linux host cannot compile it: no darwin clang, no macOS SDK
  sysroot. The Makefile already documents this at lines 115 and 144-147
  ("darwin builds: Xcode Command Line Tools"; "The darwin tray targets DO need
  cgo; Windows does not"), and uses `CGO_ENABLED=1` for both
  `cross-otto-tray-darwin-{arm64,amd64}` targets (lines 129, 134).
- With cgo OFF, the load fails outright. The planner ran
  `CGO_ENABLED=0 GOOS=darwin GOARCH=arm64 go vet ./cmd/otto-tray/` and got 11
  undefined-symbol errors from `systray.go` (`setInternalLoop`, `nativeLoop`,
  `nativeStart`, `registerSystray`, `quit`, ...) followed by "too many errors" —
  because dropping cgo removes the only darwin implementation of those symbols.

So the cheap option does not exist. There is also file-local precedent: the
`publish-dry-run` job at line 173 already sits on `macos-latest` with a comment
naming the identical cgo/sysroot constraint. Read that comment; the new job's
comment should rhyme with it rather than restate it at length.

**Finding 2 — lint scope must be `./...`, not `./cmd/otto-tray/...`.**

Three reasons, in order of weight:

1. `internal/procstat/procstat_other.go` is tagged `//go:build !linux &&
   !windows`. That IS the darwin arm of `procstat` — on `ubuntu-latest` the
   compiler picks `procstat_linux.go` and never sees it. It is outside
   `cmd/otto-tray`, so a package-scoped job would leave a known darwin-only
   file unlinted, which is the exact failure this task exists to fix.
2. `./...` is byte-identical to what `make lint` runs (Makefile line 43), so a
   developer's local mac run and the CI job are the same command. That property
   is what makes the local verification in Task 2 a meaningful proxy at all.
3. Future darwin-tagged files anywhere in the module are covered automatically.

The cost is re-linting the OS-agnostic packages `lint-test-arch` already
covered. That is cheap relative to spinning the runner at all.

**Finding 3 — the darwin arm is currently clean, so the job should go green.**

The planner ran
`go run github.com/golangci/golangci-lint/v2/cmd/golangci-lint@v2.12.2 run ./...`
at HEAD `488698e` on this macOS box: **`0 issues.`** That HEAD contains both
gp6 fixes (`dd871d0` wrapcheck, `28bf084` unparam). This is a fact about the
tree as it stands, not a prediction — re-confirm it in Task 2 against whatever
the tree actually is at execution time.

**Finding 4 — `macos-latest` is arm64, and that is full coverage.**

GitHub's `macos-latest` is Apple silicon, so the job lints `darwin/arm64`. A
repo-wide scan of `//go:build` lines found no GOARCH-conditional Go source
(`rsrc_windows_amd64.syso` is a linker artifact, not a build-tagged .go file),
so `darwin/arm64` and `darwin/amd64` see identical source. One arch is enough;
do not add an arch matrix.
</analysis_findings>

<job_block>
The exact YAML to insert. Anchor: immediately AFTER the last line of the
`lint-test-arch` job (`        run: govulncheck ./...`, currently line 117) and
immediately BEFORE the `  cross-compile-smoke:` job key (currently line 119),
separated by one blank line on each side. Two-space job indent, matching
siblings.

```yaml
  # Lints the darwin build arm, which ubuntu-latest structurally cannot see.
  # cmd/otto-tray is //go:build darwin || windows and seven of its files are
  # darwin-only (desktop_darwin.go, openfolder_darwin.go, autostart_darwin.go,
  # pidfile_darwin.go, uihelpers_darwin.go, trayhooks_darwin.go,
  # desktopconsole_darwin.go). On the linux runner every one is dropped by
  # build tag, so before this job they were linted nowhere — two real findings
  # (an unwrapped pgrep error, a per-GOOS unparam case) survived until a
  # developer happened to run `make lint` on a mac (quick task 260725-gp6).
  lint-darwin:
    name: golangci-lint (darwin arm)
    # macos-latest rather than ubuntu-latest with a GOOS override: golangci-lint
    # type-checks a package before any linter runs, and cmd/otto-tray pulls in
    # github.com/energye/systray, whose darwin implementation is cgo. A linux
    # host has no darwin clang/sysroot to build it, and turning cgo off does not
    # rescue it — the package then has no darwin implementation at all and the
    # load dies on undefined symbols. Same constraint the publish-dry-run job
    # below documents for `make package-all`.
    runs-on: macos-latest
    # No `needs:` — decoupled from lint-test-arch so a darwin-only regression
    # reads as its own red X in the PR check list. This is the second macOS
    # runner in the workflow; the extra minutes are the price of the build arm
    # having no coverage at all, which is how the two findings above survived.
    timeout-minutes: 15
    steps:
      - name: Checkout
        uses: actions/checkout@v4

      - name: Set up Go (from go.mod)
        uses: actions/setup-go@v5
        with:
          go-version-file: go.mod
          cache: true

      # Scope is ./... , not ./cmd/otto-tray/... . The tray holds most of the
      # darwin-tagged code but not all of it: internal/procstat/procstat_other.go
      # is `!linux && !windows`, so the linux runner compiles procstat_linux.go
      # and never sees it. ./... also keeps this identical to `make lint`, so a
      # developer's local mac run is the same command CI runs. Re-linting the
      # OS-agnostic packages lint-test-arch already covered is the cheap price.
      - name: golangci-lint (darwin)
        uses: golangci/golangci-lint-action@v7
        with:
          version: ${{ env.GOLANGCI_LINT_VERSION }}
          args: --timeout=5m
```
