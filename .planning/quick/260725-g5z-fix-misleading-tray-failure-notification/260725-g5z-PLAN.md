<objective>
Fix the misleading tray failure notification on Windows and macOS. Every failure
toast currently reads `Failed to start: loaded env file: C:\Users\you\.gw\.env`,
because the gw wrapper writes that routine line to stderr on EVERY invocation
(deliberately — REL-TRAY-06 reserves stdout for the support-bundle path) and the
tray blindly renders the first stderr line. The real cause (e.g. kiro-cli not on
PATH) is buried below it. Hit for real on a fresh Windows laptop install.

Purpose: The operator sees the actual failure in the notification instead of a
line that reads like ".env failed to load".
Output: A `firstMeaningfulLine` helper that skips known-informational wrapper
lines, a unit test file for it, and all five failure-notification call sites
migrated to it.
</objective>

**The exact informational lines the wrappers emit.** Both wrappers emit the same
two, with the SAME lowercase spelling. `scripts/gw` line 563 emits

the colon-terminated prefixes covers both spacings.

**The wrapper side is out of scope.** `scripts/gw.ps1` lines 433-441 document
REL-TRAY-06 (T-6) explicitly: `Initialize-Config` must route to stderr so
`Invoke-Support` keeps stdout reserved for the archive path as the sole line. Do
not change either wrapper.

**There are exactly five call sites, all of which should migrate.**
`cmd/otto-tray/tray.go` lines 440 / 447 / 455 (`handleStart` / `handleStop` /
`handleRestart`, all shelling out to the wrapper) and
`cmd/otto-tray/desktoptray.go` lines 172 (`runDesktopInstall`) and 270
(`handleDesktopStop`). Line 211 of `desktoptray.go` renders `err.Error()`, not
stderr — leave it alone. `tests/e2e/pool_sessions_e2e_test.go` has a local
variable of the same name in a different package; unrelated.

**The legacy helper must be DELETED, not kept.** After all five sites migrate it
has zero remaining references anywhere in the module, and `.golangci.yml` enables
the `unused` linter with "warnings are CI hard failures". Leaving it behind fails
the CI gate. The planning brief said "keep it if other call sites still need it"
— the check was run, and none do.

**The new helper is a strict behavioral superset of the old one**, so migrating
the two desktop sites (whose child processes are installers, not the wrapper) is

line the two functions agree, including `""`, whitespace-only, and
