# Quick Task 260812-r25 — ACP Capture card control polish

Polish the ACP Capture (diagnostics) card on `/admin`. Today the card has two
plain text buttons (Enable/Disable, Clear) and a bare `raw JSON` anchor that
navigates the current tab to an unformatted single-line JSON dump.

## Tasks

### Task 1 — Pretty-print the capture JSON (`internal/admin/capture.go`)

- Add `?pretty=1` (also accept `true`) support to `GET /admin/api/acp-capture`.
- `writeJSONCapture` grows a `pretty bool` parameter; when set, the encoder uses
  `SetIndent("", "  ")`.
- POST path is unaffected (pretty is gated on `req.Method == http.MethodGet`,
  and the POST handler tail-calls the GET handler with a POST request).

**Verify:** `go test ./internal/admin/...` passes; `curl '…?pretty=1'` returns
indented JSON, `curl '…'` returns the existing compact form.

### Task 2 — Icon buttons + new-tab raw view (`dashboard.html.tmpl`, `admin.js`, `admin.css`)

- Replace `<a href="api/acp-capture">raw JSON</a>` with a
  `<a class="gw-btn gw-btn--icon" href="api/acp-capture?pretty=1" target="_blank"
  rel="noopener">` button labeled **Show Messages**, carrying a
  `code-bracket-square` inline SVG.
- Add inline SVGs to the toggle (play-circle for Enable, stop-circle for
  Disable — both present in markup, CSS picks one from an `is-on`/`is-off`
  class) and to Clear (trash).
- The toggle no longer stores its state in `textContent`; `renderAcpCapture`
  sets `is-on`/`is-off` and updates a dedicated `[data-acp-capture-toggle-label]`
  span. The click handler reads the class, not the text.
- Icon markup follows the existing `base.html.tmpl` theme-toggle convention
  (inline SVG, `stroke="currentColor"`, `aria-hidden="true"`, CSS-driven
  visibility).

**Verify:** `go build ./...`; dashboard renders; the Show Messages button opens
a new tab.

### Task 3 — Semantic toggle colors (`admin.css`)

- Green when the button reads **Enable**, red when it reads **Disable**.
- New `:root` tokens `--gw-btn-success` `#0B7A4A` / `--gw-btn-danger` `#C42B2B`
  with white text. Deliberately NOT `--gw-healthy`/`--gw-failed`: those are
  tuned as *foreground* colors against the card, and as button fills they fall
  below 4.5:1 against white text in at least one theme. The two new fills clear
  5:1 with `#FFFFFF` and are theme-independent (the button paints its own
  background), so one pair covers both themes.

**Verify:** golangci-lint + gofumpt gates clean (embedded assets only, but the
Go change in Task 1 must pass).
